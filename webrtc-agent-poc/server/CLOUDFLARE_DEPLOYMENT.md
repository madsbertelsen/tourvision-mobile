# Cloudflare Workers Deployment Guide

This server has been converted to use **Cloudflare Workers** with **Durable Objects** instead of Fly.io.

## Architecture Overview

### Before (Fly.io):
- Express.js HTTP server
- `ws` library for WebSocket
- Docker container deployment
- Static file serving from filesystem

### After (Cloudflare Workers):
- Cloudflare Workers (serverless edge compute)
- Native WebSocket API
- Durable Objects for stateful WebSocket connections
- Cloudflare Workers Assets for static files

## Project Structure

```
server/
├── src/
│   ├── worker.ts                    # Main Worker entry point (NEW)

```

## Deployment

### Prerequisites

1. **Cloudflare Account**: Sign up at https://cloudflare.com
2. **Wrangler CLI**: Already installed via npm

### First-Time Setup

1. **Login to Cloudflare**:
   ```bash
   npx wrangler login
   ```

2. **Configure Environment Variables** (in Cloudflare dashboard):
   - Go to Workers & Pages > tourvision-server > Settings > Variables
   - Add secrets:
     - `TURN_KEY_ID` - Your Cloudflare TURN API key ID
     - `TURN_KEY_API_TOKEN` - Your TURN API token

### Deploy

```bash
npm run deploy
```

This will:
1. Compile TypeScript to JavaScript
2. Bundle the worker code
3. Upload static assets from `client/dist-public`
4. Deploy to Cloudflare's global edge network
5. Create/update Durable Objects

### View Logs

```bash
npm run tail
```

## Key Differences

### WebSocket Handling

**Express (old)**:
```typescript
import { WebSocket } from 'ws';
ws.on('message', (data) => { ... });
ws.send(message);
```

**Cloudflare Workers (new)**:
```typescript
// Native WebSocket API
ws.addEventListener('message', (event) => { ... });
ws.send(message);
```

### Static File Serving

**Express (old)**:
```typescript
app.use(express.static(clientDistPath));
```

**Cloudflare Workers (new)**:
```toml
# wrangler.toml
[assets]
directory = "./client/dist-public"
binding = "ASSETS"
```

### State Management

- **Express**: In-memory state (lost on restart)
- **Durable Objects**: Persistent state per document, distributed globally
  - **Note**: The free plan requires **SQLite-backed Durable Objects** (using `new_sqlite_classes` in migrations)

## URLs

### Local Development
- Landing Page: `http://localhost:8787`
- Editor (standalone): `http://localhost:8787/editor` (or `/editor.html`)
- Document Editor: `http://localhost:8787/doc/:documentId`
- WebSocket: `ws://localhost:8787/signaling/:documentId`
- Debug WS: `ws://localhost:8787/debug-ws`
- API: `http://localhost:8787/api`
- TURN: `http://localhost:8787/api/turn-credentials`

### Production (after deploy)
- Landing Page: `https://tourvision-server.workers.dev`
- Editor (standalone): `https://tourvision-server.workers.dev/editor` (or `/editor.html`)
- Document Editor: `https://tourvision-server.workers.dev/doc/:documentId`
- WebSocket: `wss://tourvision-server.workers.dev/signaling/:documentId`

**Note:** Cloudflare Workers Assets automatically provides clean URLs without the `.html` extension. Both `/editor` and `/editor.html` will work (the latter redirects to the former).

**Document URLs:** Use `/doc/:documentId` to open a specific document in the editor. These URLs are generated by the landing page when you click on a trip.

## Advantages of Cloudflare Workers

1. **Global Edge Network**: Deployed to 200+ locations worldwide
2. **Zero Cold Starts**: Instant response times
3. **Automatic Scaling**: Handles millions of requests
4. **Cost Effective**: Free tier includes 100k requests/day
5. **No Docker**: No container management needed
6. **WebSocket Native**: Built-in WebSocket support
7. **Durable Objects**: Stateful coordination for real-time apps

## Troubleshooting

### Landing Page Not Showing at Root URL

**Problem:** The root URL (`/`) serves the editor instead of the landing page.

**Cause:** Cloudflare Workers Assets automatically serves `index.html` for the root path, bypassing Worker redirect logic.

**Solution:** Rename the files in `client/dist-public`:
```bash
cd client/dist-public
mv index.html editor.html    # Editor becomes editor.html
mv landing.html index.html   # Landing becomes the default index.html
```

Then redeploy: `npm run deploy`

The editor will now be accessible at `/editor.html` and the landing page at `/`.

### Assets Not Loading

Make sure the client build exists:
```bash
ls -la client/dist-public
```

If missing, build the client first:
```bash
cd ../client
npm run build
# Copy output to server/client/dist-public
```

### WebSocket Connection Fails

Check that you're using the correct protocol:
- Local: `ws://` (not `wss://`)
- Production: `wss://` (not `ws://`)

### Durable Object Errors

**Error: "must create a namespace using a 'new sqlite classes' migration"**

This error occurs on the **free plan**. The fix:

1. Update `wrangler.toml` to use `new_sqlite_classes` instead of `new_classes`:
   ```toml
   [[migrations]]
   tag = "v1"
   new_sqlite_classes = ["SignalingDurableObject"]  # Use this for free plan
   ```

2. Redeploy: `npm run deploy`

Durable Objects need to be migrated on first deploy. This happens automatically,
but if you see errors, check the Cloudflare dashboard for migration status.
